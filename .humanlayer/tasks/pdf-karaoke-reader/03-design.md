This document says how those behaviours are met.

## The one interesting algorithm

Kokoro gives audio, not timestamps. `build_timeline` reconstructs them:

1. Split the page's words into sentences (`split_sentences`), keeping each
   sentence's *word indices* so the mapping back to highlight boxes survives.
2. Synthesise each sentence separately → exact duration from the WAV header.
3. Within a sentence, `allocate(words, duration)` splits the duration in
   proportion to each word's **speech cost**:

   ```
   cost(word) = 1.0                       base, so no word can vanish
              + 0.55 * vowel_groups(word) syllables dominate speaking time
              + 0.08 * len(letters)       long words take longer to say
              + pause_weight(trailing punctuation)   , ; : → 0.4   . ! ? → 0.9
   ```

   Then `span_i = duration * cost_i / sum(cost)`, laid end to end.
4. Concatenate the sentence audio and offset each sentence's spans by the
   running total.

Sentence boundaries are therefore exact and drift cannot accumulate across a
page; only the within-sentence split is an estimate. Every guarantee the UI
relies on — total cover, no overlap, order, positivity, monotonicity — is a
property of `allocate` and is tested as one.

`word_at(timeline, t)` is a binary search returning the unique span containing
`t`; `activeIndex()` in TypeScript is the same function and is property-tested
against a linear scan with Hegel.

## API

| Route | Returns |
|---|---|
| `POST /api/documents` (multipart `file`) | `{id, page_count, pages: [{index, width, height, words: [{text, x0, y0, x1, y1}]}]}` |
| `GET /api/documents/{id}/pages/{n}/narration?voice=am_adam` | `{audio_url, duration, spans: [{word_index, start, end}]}` |
| `GET /api/documents/{id}/pages/{n}/audio.wav` | the synthesised WAV |
| `GET /api/health` | `{status, voice, synthesizer}` |

Documents live in an in-process dict. This is a local prototype; persistence is
an explicitly deferred decision (ADR 0005).

## Substituting the model in tests

`SpeechSynthesizer` is a `Protocol` with one method. `FakeSynthesizer` returns a
silent WAV whose length is a deterministic function of the text, so the whole
BDD suite runs with no model, no download, and no wall-clock cost — while the
real `KokoroSynthesizer` is exercised by a separate marked test and by the
running app.

## What the docs get

Scenarios tagged `@docs` run under Playwright and write their screenshots to
`docs/assets/generated/<scenario-slug>/`, which the Diátaxis pages embed. A GIF
of the karaoke highlight is recorded through `chrome-mcp-server`. Scenarios
tagged `@property` produce no artefacts.
