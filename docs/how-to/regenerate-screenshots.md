# Regenerate the documentation screenshots

Every image in this site is written by a test. If the interface changes, the
images do not go stale — a test fails.

## Regenerate them

```bash
make test-e2e
```

That runs the scenarios tagged `@docs` in `features/` against a real browser, a
real API and the real Kokoro model, and writes each screenshot to
`docs/assets/generated/<scenario-slug>/`. Then:

```bash
make docs
```

## What is actually happening

The tag is the mechanism. In `features/karaoke.feature`:

```gherkin
@docs
Scenario: Pressing play starts the narration and lights the first word
```

`@docs` marks a scenario as a worked example — concrete nouns, a written
expectation — and those are the ones whose screenshots are worth showing a
reader. Scenarios tagged `@property` run against generated input and produce no
images, because a shrunk counterexample is optimised for brevity, not for
someone trying to learn the interface.

Because pytest-bdd turns Gherkin tags into pytest markers, `-m docs` is all it
takes to select them.

## When a screenshot changes

A changed image means one of two things, and you have to decide which:

- **The interface improved.** Commit the new screenshots along with the code.
  The docs are now correct again, automatically.
- **Something broke.** The screenshot is telling you before a user does.

This is the whole reason for the rule in
[ADR 0004](../explanation/adr/0004-documentation-images-are-test-output.md): an
image that cannot be regenerated by a passing test is a build failure, not a
stale file somebody might eventually notice.

## Adding a new screenshot

Take it inside a `@docs` step definition, with the shared `shot` fixture. It
derives the scenario slug automatically, so you only pass the file name:

```python
shot("04-jumped")
```

then reference it from a docs page:

```markdown
![Clicking a word moves the narration to it](../assets/generated/clicking-a-word-jumps-the-narration-to-it/04-jumped.png)
```

If you reference an image no scenario produces, `mkdocs build --strict` fails —
which is the point.

## Regenerate the behaviours reference too

The Reference page listing every scenario is generated from the feature files:

```bash
uv run python scripts/gen_behaviours.py
```

Edit `features/*.feature`, never `docs/reference/behaviours.md`.
